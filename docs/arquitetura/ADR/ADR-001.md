# ADR-001: Código em inglês, textos de UI em português via camada de i18n

**Data:** 22/06/26
**Status:** Aceita
**Decisores:** Humano (thiagoroddev), IA (agente geral-robusto)

## Contexto

A REV-001 (achado **REV-001-A05**) identificou uma divergência entre a convenção declarada e a realidade do código:

- O núcleo do pacote do agente (`01-nucleo.md` §2.4) declara **Português** como idioma único do projeto (variáveis, funções, componentes, tipos, comentários, testes).
- O código real está majoritariamente em **inglês**: identificadores (`RouteSimpleTable`, `getCommercialBadgeClasses`, `searchAT`, `RowData`) e comentários/docstrings em inglês (`App.tsx`, `types/index.ts`, `pages/RouteViewer.tsx`, `utils/excelProcessor.ts`), enquanto **os textos exibidos ao usuário** estão em português, centralizados em `src/constants/uiLabels.ts`.

O próprio `uiLabels.ts` já antecipa internacionalização: o comentário do topo diz _"To add more languages, create uiLabels.en.ts, uiLabels.es.ts, etc."_. Ou seja, a separação entre "idioma do código" e "idioma da interface" já existe de fato — falta apenas oficializá-la, porque a convenção atual (tudo em PT) é cara de cumprir (exigiria renomear todo o código) e contraria o padrão de fato.

Precisamos decidir o idioma do projeto de forma consciente, já mirando suporte a múltiplos idiomas na interface.

## Decisão

**Adotamos dois idiomas com fronteira clara:**

1. **Código em inglês.** Identificadores (variáveis, funções, componentes, tipos, hooks), nomes de arquivo e comentários/docstrings em **inglês**. Isso reflete o padrão de fato e alinha com as APIs externas (React, Leaflet) que já são em inglês.

2. **Textos de usuário (UI) preparados para internacionalização (i18n).** Toda string visível ao usuário fica centralizada na camada de labels (`src/constants/uiLabels.ts`), **nunca hardcoded em componentes**. O **português é o idioma inicial (default)**; a estrutura permite adicionar `uiLabels.en.ts`, `uiLabels.es.ts` etc. sem tocar nos componentes.

Esta ADR **substitui**, para este projeto, a regra de "idioma único = Português" do núcleo §2.4. O `docs/contexto-projeto-ai.md` (a criar — REV-001-A02) deve registrar esta decisão como convenção vigente.

## Consequências

### Positivas

- Alinha a convenção com o padrão de fato — sem renomear o código inteiro.
- Fronteira clara código(EN)/UI(PT) elimina a ambiguidade do "idioma misturado".
- Caminho de internacionalização já fica aberto: trocar idioma da UI é adicionar um arquivo de labels, não mexer em componentes.
- Comentários/identificadores em inglês mantêm consistência com bibliotecas e ecossistema.

### Trade-offs Aceitos

- **Diverge do default do pacote (PT):** aceito porque a §1.3 do núcleo permite que decisões do projeto vençam regras gerais, e esta é registrada formalmente.
- **Exige disciplina de não hardcodar texto na UI:** aceito; vira item de checklist de revisão (toda string visível passa por `UI_LABELS`).
- **Comentários legados em PT espalhados:** existem poucos; serão convertidos para EN oportunisticamente quando o arquivo for tocado (não há tarefa de tradução em massa).

## Alternativas Descartadas

### Alternativa 1: Traduzir todo o código para português (cumprir o núcleo §2.4 literalmente)

**Por que descartada:**
- Custo altíssimo: renomear identificadores em ~49 arquivos, quebrar familiaridade com APIs em inglês.
- Não agrega valor ao produto; é retrabalho puro.
- Vai contra o padrão de fato já consolidado.

### Alternativa 2: Manter tudo como está sem decisão formal

**Por que descartada:**
- A divergência convenção-vs-código continua sendo um achado recorrente em revisões.
- Sem fronteira oficial, surge texto hardcoded e mistura idiomática nova.

### Alternativa 3: Biblioteca de i18n completa (react-i18next) agora

**Por que descartada (por ora):**
- Overkill para um único idioma ativo (PT). A camada `uiLabels.ts` já cobre a necessidade atual e permite evoluir para uma lib quando houver um segundo idioma real em uso.
- Adicionar dependência sem demanda concreta contraria o anti-padrão de instalar dependência sem necessidade.
