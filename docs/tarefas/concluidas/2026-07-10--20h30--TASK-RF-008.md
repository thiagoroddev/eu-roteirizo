## Decisões Tomadas

- **RN-21 como chave do banco, não como regra de código.** A chave composta `[manifestId, routeName]` torna "1 roteiro por rota" impossível de violar — o teste de sobrescrita É o teste da regra.
- **Pausa do auto-save durante o draft** (achado do planejamento): `REOPEN_STOP` move a parada para fora de `stops`; um snapshot no meio da edição salvaria o roteiro **sem** a parada aberta. O snapshot pré-edição vale até Salvar/Cancelar.
- **`persistReady` antes de qualquer escrita** (achado da execução): a ordem hidratar-depois-salvar não é opcional — invertida, o primeiro render vazio apagaria o dado que ia carregar.
- **Totais honestos no Sumário:** pernas de veículo em linha reta (haversine), mesmas estimativas que o painel já mostra — rotulado no código como o "coarse" que RF-006.7/007 refinam. Nada de números de grafo que ainda não existe.
- **DB separado** (`danfo-roteiros`), não um store novo no `danfo-manifests`: evita bump de versão + upgrade coordenado num serviço estável.

## Aprendizados Para o Projeto

- **Auto-save + hidratação assíncrona = corrida armada.** Qualquer feature futura com "carregar ao montar + salvar ao mudar" precisa do gate `persistReady` — o estado inicial vazio é indistinguível de "usuário apagou tudo".
- **`tsc --noEmit` na raiz ≠ `tsc -b` do build**: o segundo cobre os testes com o config estrito. Rodar o build no gate não é redundância.
