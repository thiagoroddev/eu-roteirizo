## Decisões Tomadas

- **Sem `cross-env`:** `test.env` do Vitest cobre `npm run test` e `npx vitest` direto — dependência nova seria redundante.
- **`NODE_ENV: ""` (vazio) no settings do Claude:** o mapa `env` não remove variáveis; vazio neutraliza (npm não omite dev; React não resolve produção; Vitest seta `test` sozinho).
- **Vírgulas finais do settings do VS Code mantidas:** o arquivo é JSONC e usa esse estilo em todos os blocos — "corrigir" só ali seria inconsistente.

## Aprendizados Para o Projeto

- Repo agora **tolera ambiente hostil**: `include=dev` no `.npmrc` e `test.env` no Vitest significam que `NODE_ENV=production` vazado não quebra mais install nem testes — vale como padrão para qualquer projeto novo na mesma máquina.
- O mapa `env` do `settings.json` do Claude Code é o jeito certo de sanear o ambiente das sessões quando o injetor está fora do alcance (extension host).
