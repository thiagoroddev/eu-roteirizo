## Planejamento Aprovado

### Problema (evidência)
`src/components/RouteMap.tsx:153-167` — `tooltipContent` é uma string HTML que interpolava campos crus do Excel (`DESTINATION_ADDRESS`, `NEIGHBORHOOD`, `SEQUENCE`, `STOP`, `ZIPCODE`) e era passada a `marker.bindTooltip(tooltipContent, ...)`, que renderiza HTML. Markup numa célula (ex.: `<img src=x onerror=...>`) seria injetado no DOM.

### Fix
1. Novo helper `src/utils/escapeHtml.ts`: `escapeHtml(value: unknown): string` que converte para string (`null`/`undefined` → `""`) e escapa `& < > " '` (ampersand primeiro, para não duplo-escapar).
2. `RouteMap.tsx`: cada valor dinâmico do `tooltipContent` agora passa por `escapeHtml(...)` — campos do Excel e os rótulos de status (defesa em profundidade). HTML estrutural (`<strong>`, `<br/>`) permanece literal.
3. Teste `src/__tests__/utils/escapeHtml.test.ts` (6 casos).

## Decisões Tomadas
- **Helper de escape em vez de construir o tooltip via DOM (`textContent`):** mínimo e cirúrgico, mantém o layout HTML existente; o helper é reutilizável e testável isoladamente.
- **Escapar também os rótulos de status (`getCommercialDisplayStatus`, `formatDeliveryLabel`):** embora venham de constantes controladas, escapar tudo uniformemente é defesa em profundidade e evita regressão se a origem mudar.
- **`escapeHtml` aceita `unknown`:** os valores de célula podem ser string/number/etc.; centraliza a coerção para string.
