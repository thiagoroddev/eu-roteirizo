## Decisões Tomadas

- **Toggle em vez de duas seções empilhadas:** reusa o `MapModeToggle` (que era genérico por construção — só faltavam os textos), então a metáfora "Original × Meu roteiro" é a MESMA do mapa. Abre em Meu Roteiro quando há roteiro.
- **"Ver no Mapa" contextual, um só:** com o toggle decidindo o que se vê, dois botões de mapa competiam com ele.
- **Campo sem dado SOME** (em vez de "—"): a rota única tem menos colunas e a tela encolhe em vez de virar parede de "Sem dados". Custo: o layout muda de forma entre romaneios — aceito pelo humano.
- **Barras de fluxo no lugar dos cards de total:** a barra dá total E composição; um card repetindo o número era ruído (achado dos dois smokes — primeiro o tempo, depois a distância).
- **4 cards no vocabulário do painel** (Endereços/Pacotes/Paradas/Comercial): as duas telas passam a nomear as mesmas coisas do mesmo jeito.
- **`isMissingValue` por sentinela** (compara com "Sem dados"/"Dado inválido"/"-"): a camada de dados devolve string pronta; o conserto limpo (status + valor) ficou fora de escopo, anotado.
- **Estado do roteiro com `deliveredRatio` opcional:** os 3 estados existem, mas o percentual de execução entra por parâmetro — a RF-009 alimenta sem mexer em chamador nenhum.

## O Que NÃO Foi Feito (e Por Quê)

- **Percentual real de execução:** nada registra entrega concluída — é a **RF-009**. Hoje um roteiro com a construção fechada lê **"em execução — 0% concluído"** (limitação conhecida, aceita no smoke). O humano preferiu isso a inventar um 4º estado "pronto".
- **Refatorar a camada de dados** para devolver status em vez de string pronta: `isMissingValue` resolve agora; a versão limpa vira dívida.
- **Mover o `MapModeToggle`** para pasta neutra (segue em `components/map/` apesar de genérico).
- **Divergência tipográfica** do Original (`formatDistance` emite "1.2 km" com ponto, enquanto o roteiro usa `formatMeters`).

## Aprendizados Para o Projeto

- **Um controle "genérico por construção" só precisa dos textos parametrizados:** o `MapModeToggle` não tinha nenhuma dependência do mapa — bastou receber labels/aria para servir o Sumário. Vale checar isso antes de escrever um segundo componente igual.
- **Barra de composição > card de total:** quando existe a decomposição, a barra responde "quanto" e "de quê" no mesmo espaço; o card do total vira redundância. Os dois smokes chegaram a essa conclusão de forma independente (tempo e depois distância).
- **Camada de dados que devolve string pronta ("Sem dados") impede a UI de diferenciar vazio de valor** — a sentinela resolve, mas é sintoma: dado + status separados seriam mais honestos.
- **Fixture pobre é bom detector de layout adaptativo:** as 3 asserções que quebraram provaram que o "campo sem dado some" funciona — o teste é que estava ancorado no lugar errado.
