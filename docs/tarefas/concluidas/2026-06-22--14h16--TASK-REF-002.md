## Decisões Tomadas
- **Aceitar `key={idx}` em vez de forçar chave de conteúdo:** sem campo único garantido, uma chave de conteúdo poderia colidir (warning React) — regressão. Para lista estática que não reordena, `idx` é a escolha correta (doc do React). Registrado por comentário no código + "Aceito sem ação" na REV.
- **Não implementar id sintético no parse (alternativa B):** seria a única forma de ter chave única estável reordenação-safe, mas é over-engineering para tabelas que hoje não reordenam/filtram. Fica como possibilidade futura se a UI ganhar ordenação/filtro client-side.

## O Que NÃO Foi Feito (e Por Quê)
- **Id sintético estável por linha (`__rowId`) no excelProcessor:** não feito; só valeria se as tabelas passassem a reordenar/filtrar no cliente. Pode virar TASK-REF futura nesse cenário.
