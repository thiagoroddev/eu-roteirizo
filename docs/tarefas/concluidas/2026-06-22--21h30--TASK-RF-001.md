## Decisões Tomadas

- **Ir direto ao Nível B (roteamento local), não ao Nível A:** o requisito de ver a rua traçada com quilometragem e comparar destinos no planejamento exige o motor local. Decisão estratégica documentada em **ADR-002**.
- **A\* escrito do zero e comentado, sem biblioteca:** escolhido com o humano — sem dependência e serve de material de estudo. `ngraph.path` foi a alternativa descartada para o protótipo.
- **Pontos de teste por clique no mapa:** escolhido com o humano — mais rápido para testar vários cenários e já valida o map matching.
- **Mão única como ausência de aresta no grafo direcionado:** a restrição emerge da estrutura de dados; nenhum caminho consegue sugerir contramão.

## O Que NÃO Foi Feito (e Por Quê)

- **Velocidade/tempo de entrega e estimativas:** fora do escopo do protótipo, cujo foco era só traçado + distância.
- **Cache offline (IndexedDB) e A\* com heap:** itens de produção, não de viabilidade. Anotados para a futura migração.
- **Map matching avançado (encaixe em aresta, não só nó):** o encaixe no nó mais próximo bastou para validar; refinável depois.
- **Migração para o código do app:** intencionalmente adiada — protótipo primeiro, migração só após positivar (e positivou).

## Aprendizados Para o Projeto

- **Estrutura de dados correta torna o algoritmo trivial:** modelar a mão única como ausência de aresta elimina qualquer lógica defensiva contra contramão.
- **Prototipar a parte difícil primeiro de-risca o roadmap:** validar o motor isolado evita descobrir tarde que a abordagem não fechava.
- **"Sem API de roteirização" ≠ "sem dados de via":** baixar OSM é como baixar um mapa; o que se evita é a API que *calcula* a rota.
