## Decisões Tomadas

- **Normalizar no choke point** (`excelProcessor`, logo após o parse): um único lugar, e **todos** os consumidores passam a ver nomes canônicos sem mudança neles.
- **Alias só de variantes conhecidas + não-clobber:** seguro para o multi-rota (sem variantes → inalterado) e à prova de arquivo com a coluna canônica já presente (canônica vence). Coberto por teste.
- **`AT ID` → `Planned AT`:** faz o AT aparecer no resumo (e a data, quando o código casa `ATYYYYMMDD…`).
- **Escopo do "full":** o alias resolve o que depende de **nome de coluna** (RF-09/12/15) e a inferência (RF-18) sempre rodou pelo endereço. **RF-11 fica parcial por design** — sem `Location Type`, a classificação é só inferência; ícones "indefinidos" quando o endereço não tem complemento reconhecível. **Não é header.**

## O Que NÃO Foi Feito (e Por Quê)

- **Colorir ícones na rota única (RF-11):** impossível só com alias — depende da coluna `Location Type` (ausente) ou de inferência mais rica. Fica como limitação conhecida do dado; não virou tarefa (não há o que "consertar" no header).
- **Validação visual:** a camada de dados está verificada (testes + rastreio); a conferência na tela fica com o humano.
- **Variantes especulativas (lançamento nacional):** `COLUMN_ALIASES` é extensível, mas só incluí as do arquivo real (não inventar).

## Aprendizados Para o Projeto
- **Normalizar cabeçalhos num único ponto** é mais barato que ensinar cada consumidor a entender variantes — e mantém o multi-rota intocado de graça.
- **"Destravar" ≠ "ficar igual":** o alias libera dados de coluna, mas o que depende de **conteúdo** (inferência de tipo pelo endereço) tem teto próprio — separar as duas coisas evita prometer demais.
