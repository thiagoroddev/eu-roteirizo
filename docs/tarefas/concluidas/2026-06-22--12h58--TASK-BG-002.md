## Planejamento Aprovado

### Problema (evidência)
`src/utils/excelProcessor.ts:181-233` — bloco de logging detalhado rodava sempre (sem flag). As linhas 203-208 montavam `dataRows` com o **conteúdo das células** das linhas ignoradas e logavam via `console.warn`, expondo endereço, CEP, bairro e cidade de destinatários no console do navegador em produção.

### Fix (2 camadas)
1. **Gate por ambiente:** todo o bloco de logging detalhado (`try/catch`) envolvido em `if (import.meta.env.DEV) { ... }`. Em produção (`DEV === false`) nada é logado. `import.meta.env.DEV` tipa via `"types": ["vite/client"]` (tsconfig.app.json) — sem novo arquivo.
2. **Redação de PII em DEV:** parou-se de logar o valor das células. O log de linhas ignoradas agora mostra apenas os **nomes das colunas preenchidas** (`filledColumns = ...`), preservando utilidade de debug sem expor conteúdo. `idx`/`reason`/`missingColumns` (não-PII) permanecem.

`console.error(err)` (tratamento de erro geral) mantido — não é PII e gatear esconderia erro real em produção.

## Decisões Tomadas
- **`import.meta.env.DEV` em vez de uma flag DEBUG customizada:** padrão do Vite, sem dependência nova, e `false` automaticamente em build de produção.
- **Logar nomes de colunas em vez dos valores:** a utilidade de debug (saber quais campos vieram preenchidos numa linha ignorada) é mantida; o conteúdo sensível some até do console em DEV.
