## Decisões Tomadas
- **String builder, não componente React.** O SVG é injetado no `divIcon` via `html`; gerar string é mais leve (marcadores re-renderizam muito) e trivial de testar. Espelha o `createMarker` do protótipo.
- **Cor como valores (`top`/`bottom`/`glow`/`numberInk`), não um `type` semântico.** É o único jeito de reusar no roteiro (paleta categórica, cor arbitrária). O mapa tipo→cor do Original (verde/azul/cinza + número escuro no cinza) mora na **.2**.
- **Glow inline em vez de classe CSS global.** Mantém o builder autocontido (testável isolado, sem depender de stylesheet). CSS só para o reset do `divIcon` (responsabilidade do wrapper Leaflet).
- **Local `utils/markers/`** (não `components/`): o artefato é função geradora (sem JSX), paralelo direto ao `mapIcons.ts` que vai aposentar (na .2) e ao padrão `utils/routing/`.

## O Que NÃO Foi Feito (e Por Quê)

## Aprendizados Para o Projeto
- **`L.divIcon` desenha uma caixa branca por padrão** (`.leaflet-div-icon` tem `background:#fff;border`): qualquer marcador SVG/HTML custom precisa de um reset de CSS no `className`, senão aparece o quadradão atrás do ícone.
- **`id` de `<linearGradient>` precisa ser único (ou determinístico) entre marcadores** no mesmo documento: `url(#id)` resolve para o **primeiro** id casado no DOM; ids repetidos fazem todos os marcadores herdarem o gradiente do primeiro. Derivar o id da cor resolve sem abrir mão da pureza.
- **Builder autocontido (glow inline) > CSS global** quando a peça precisa ser testada isolada e reusada com cor variável: o efeito viaja junto com a prop, não depende de uma classe pré-definida.
