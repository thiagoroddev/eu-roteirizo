## Planejamento Aprovado

**Problema:** o app guarda os **bytes crus** do XLSX e roda `processExcelFile` **de novo** a cada montagem de Sumário/Mapa — parse SheetJS do arquivo inteiro + agrupamento das 153 rotas para exibir **uma**. O guard `loadedRef` é por instância do hook, então Sumário↔Mapa reprocessa. Rota única não é otimizada: é o mesmo caminho com arquivo pequeno. Saída escolhida pelo humano: **letra (c)** da DT-007 — gravar linhas agrupadas por rota, lendo só a rota pedida.

**Achado da exploração que sustenta o plano:** ninguém consome as linhas de **todas** as rotas. `RoutesPage`/`ManifestCard` usam só `ManifestMeta` (nomes/AT/contagem); `HomePage` usa `routes` como booleano; Sumário/Mapa usam `currentRows` (uma rota). Os `bytes` crus têm **um único** consumidor: o próprio reprocessamento.

**O que muda:**
- `types/manifest.ts`: `ManifestMeta` ganha `availableCols?`/`missingCols?` (o Sumário precisa deles; hoje só existem no `ProcessedResult` em memória). **`isSingleRoute` NÃO é adicionado** — ele já é `kind === "single"` (evitar campo redundante; desvio consciente do plano original).
- `services/manifestStorage.ts`: DB `danfo-manifests` **v1 → v2**, novo store `routeRows` com chave composta `[manifestId, routeName]` (mesmo idiom do `routeStorage`). `saveManifest` grava as linhas por rota + os cols no record. Novo `getRouteRows(id, rota)` (uma leitura por chave, sem SheetJS). `deleteManifest` apaga o range das linhas (sem órfãos). Novo `backfillRouteRows` para o fallback.
- `hooks/useRouteUploader.ts`: `loadManifest(id, routeName?)` — **fast path** via `getRouteRows` + meta (sem SheetJS); **fallback** reprocessa quando não há linhas gravadas (romaneios anteriores à migração) e **grava** para as próximas vezes.
- `hooks/useManifestFromUrl.ts` + `types/hooks.ts`: guard passa a ser `manifestId + routeName` (a fast path lê 1 rota; trocar de rota na mesma instância precisa recarregar — barato agora), e passa `routeName` ao `loadManifest`.
- Sumário/Mapa: o guard `routes &&` continua correto (truthy = carregado); `routes` na fast path vira `{ [routeName]: rows }` — parcial, mas ninguém lê outra rota.

**Critérios de aceite:** entrar/sair de Sumário↔Mapa num multi deixa de mostrar "Carregando…" perceptível; romaneio salvo antes da mudança continua abrindo (fallback) e fica rápido na 2ª vez; apagar romaneio não deixa resto.

**Riscos:** migração de schema sobre dados do usuário. Mitigação: v2 só **adiciona** store — nada é reescrito nem apagado, e o caminho antigo segue vivo como fallback.

**Fora de escopo:** apagar os `bytes` crus (mantidos — permitem reprocessar se o `excelProcessor` mudar).

## Decisões Tomadas

- **`isSingleRoute` derivado de `kind`, não gravado.** O plano dizia adicionar 3 campos ao `ManifestMeta`; `kind === "single"` já é `isSingleRoute`. Adicionar o campo seria redundância (anti-DRY). Adicionei só `availableCols`/`missingCols`.
- **Chave composta out-of-line `[manifestId, routeName]`** (valor = `RowData[]`, não dá keyPath inline). Range delete `IDBKeyRange.bound([id, ""], [id, "￿"])` — **espelha exatamente** o `routeStorage`, para o código ler como o vizinho.
- **Marcador da fast path = `record.availableCols` presente.** É o sinal de que o manifesto foi salvo/backfillado pós-REF-018. Ausente ⇒ fallback. `getRouteRows` retornar `[]` (rota vazia legítima) é `truthy`, distinto de `null` (miss) — a rota vazia não cai no fallback.
- **Fast path lê o record inteiro (com bytes).** É `structuredClone` (memcpy), não parse — ordens de grandeza abaixo do SheetJS que se elimina. Evitar ler os bytes exigiria separar stores = reescrever dado (fora do plano). Aceito.
- **Guard por `manifestId + routeName`.** A fast path carrega uma rota; trocar de `rota` na mesma instância do hook precisa recarregar. Barato agora (uma leitura por chave). Separador espaço no `loadKey` é seguro: o id é hex de tamanho fixo sem espaços.
- **Auto-heal de escrita parcial.** Se `writeRouteRows` falhar após o record salvo, o reopen acha `availableCols` mas `getRouteRows` = `null` ⇒ cai no fallback ⇒ reprocessa + backfilla. Sistema se conserta sozinho.

## O Que NÃO Foi Feito (e Por Quê)

- **Transação atômica record+rows.** `db.put(record)` e `writeRouteRows` são transações separadas; uma falha no meio deixa record salvo sem linhas, e `saveManifest` ainda retorna `error`. Não corrigido porque **o fallback já auto-cura** no 1º reopen e a falha de escrita (quota/modo privado) é rara. Registrado aqui; vira tarefa própria se incomodar.
- **Backfill no caminho de duplicata.** Reenviar um arquivo salvo pré-REF-018 retorna "duplicate" sem gravar linhas. Não é problema: o 1º reopen backfilla. Manter `saveManifest` simples.
- **Apagar os `bytes` crus** (decisão adiada do plano; mantidos p/ reprocessar se o parser mudar).
