## Planejamento Aprovado

### Diagnóstico — confirmado no código

**H1 é a causa-raiz, e o código fecha o caso.** O `loadRoadGraph` **nunca rejeita**: retorna `{ graph }` ou `{ error }` (graphCache.ts:117-127), e timeout/falha do Overpass viram `{ error }` → status `"error"` → botão **Repetir**. Como o humano relata **"Carregando ruas…" sem Repetir**, o load **não** cai no caminho de erro. A única forma de ficar preso em `"loading"` é o **wedge do `cancelledRef`** em useRoadGraph.ts:42-74. Isso **descarta H2 como causa primária** (H2/bbox só produziria erro+Repetir).

**Mecânica do wedge** (`points` é memoizado em `rows` → identidade estável; gatilho = *cleanup durante um load em voo*, não churn de render):
1. Entra no roteiro → `startLoad` (`cancelledRef=false`), fetch em voo.
2. Toggle p/ Original **durante** o load → cleanup faz `cancelledRef.current = true`.
3. Toggle de volta → efeito roda, mas `startedAttemptRef.current === attempt` → **return antecipado, não reinicia**.
4. Fetch resolve → `if (cancelledRef.current) return;` → **engole grafo e erro** → preso em `loading` para sempre.

**Bônus:** StrictMode (main.tsx:30) dispara o mesmo wedge no `npm run dev` se os `points` já estiverem prontos no 1º mount — reprodução limpa e independente do bbox, isolando H1 de H2.

### O que muda
- `src/hooks/useRoadGraph.ts`: substituir o `cancelledRef` **compartilhado** por um `cancelled` **local ao run** (closure capturada no cleanup). Trocar o guard "started-only" por **dois marcadores** — `startedAttemptRef` (em voo) e `completedAttemptRef` (concluído): o cleanup **libera o "started"** apenas quando o run foi cancelado **sem concluir**, preservando o "completed" para não re-buscar um grafo já pronto ao alternar modos.
- `src/__tests__/hooks/useRoadGraph.test.tsx`: cenário de regressão do wedge — desabilitar durante o load e reabilitar → chega a `ready` (não fica preso em `loading`); o run abandonado que resolve tarde é ignorado.

### Critérios de aceite (os da task)
entrar no roteiro carrega até `ready` de forma confiável (sem travar em "loading"); alternar modos no meio do load não trava; grafo pronto não re-busca ao togglar; fallback reta legítimo (offline/sem grafo) preservado; smoke no aparelho valida com rota pequena E espalhada.

### Fora de escopo
`AbortController` p/ abortar o fetch órfão (hoje o run cancelado é só ignorado — e ainda popula o cache, então o restart vira cache-hit; follow-up opcional) e o H2/bbox (DT-005, tarefa própria).

**Impacto:** só o `useRoadGraph` (1 hook) + seu teste. Sem mudança de API do hook.
**Riscos:** baixo — lógica de 2 refs local, coberta por teste dos toggles. Smoke no aparelho (só o humano faz deploy) valida o traçado real.
**Dependências novas:** nenhuma.

## Decisões Tomadas

- **Dois refs (`startedAttemptRef` + `completedAttemptRef`) em vez de um só:** distinguir "em voo" de "concluído" é o que permite (a) reiniciar um load cancelado sem completar e (b) **não** re-buscar um grafo já pronto ao alternar modos — os dois requisitos que o guard "started-only" não conseguia satisfazer juntos. Um único ref forçaria escolher entre re-buscar sempre ou travar.
- **`cancelled` local ao run (closure), não ref compartilhado:** cada execução do efeito tem seu próprio flag; um run abandonado que resolve tarde se ignora sozinho sem envenenar o próximo. Era a raiz do wedge.
- **`AbortController` ficou fora:** o fetch órfão hoje completa e **popula o cache** (`putCachedGraph`), então o restart vira cache-hit — abortar economizaria pouco e adicionaria complexidade (fiar `signal` em `fetchRoadGraph`). Anotado como follow-up opcional, não bloqueia o aceite.
- **Fix Light do lint pré-existente:** o `npm run lint` já estava vermelho por um `prettier/prettier` em `RouteMap.test.tsx:512` (commit 97ec371, série RF-006.7). Corrigido com `eslint --fix` como Modo Light (só formatação), por decisão do humano, para destravar o gate global.

## Aprendizados Para o Projeto

- **`cancelledRef` compartilhado entre execuções de efeito é uma armadilha clássica:** o flag de cancelamento deve ser **local ao run** (closure capturada no cleanup). Um ref compartilhado faz um run cancelado envenenar o próximo. Padrão a repetir em qualquer fetch-in-effect futuro.
- **Guard "load-once" precisa rastrear CONCLUSÃO, não só início.** Guardar só "começou" trava para sempre se o "começou" foi cancelado antes de terminar. Dois estados (em voo / concluído) resolvem sem re-buscar à toa.
- **Diagnóstico por eliminação via o contrato da função:** como `loadRoadGraph` nunca rejeita (só `{graph}`/`{error}`), "loading eterno **sem** botão Repetir" era prova de que o resultado estava sendo engolido — isolou H1 de H2 antes de tocar no código. Ler o contrato do serviço vale mais que reproduzir às cegas.
