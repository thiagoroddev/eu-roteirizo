## Decisões Tomadas

- **"Eu Roteirizo" como nome de exibição, `eu-roteirizo` como slug:** o humano pediu o nome em kebab-case, mas kebab-case em header de app e no manifest do PWA fica errado para o usuário final. Slug técnico e nome de exibição seguem formas diferentes da mesma identidade.
- **IndexedDB renomeado sem migração:** decisão explícita do humano depois de eu apresentar as três opções (manter / migrar / renomear seco) e o custo de cada uma. A perda de dados foi informada e aceita antes da execução.
- **Não renomear o projeto Cloudflare `pre-rota-teste`:** renomear cria projeto novo com URL nova e deixa o antigo órfão. Como as referências nos docs apontam para uma URL que **continua verdadeira**, mexer nelas tornaria a documentação falsa — o oposto do objetivo. Fora do escopo por decisão do humano.
- **Não tocar em `docs/tarefas/concluidas/`:** são registros históricos imutáveis (template 31, §Imutabilidade). Reescrevê-los faria os arquivos afirmarem coisas que não eram verdade na data que carimbam.
- **Não substituir "roteirizador" como substantivo comum:** decisão do humano. O app é um roteirizador e agora tem nome próprio; as duas coisas coexistem.

## Aprendizados Para o Projeto

- **Renome de projeto é tarefa de desambiguação, não de busca-e-substitui.** Neste repo, um único grep por "danfo|pre-rota|roteirizador" casava com quatro coisas de naturezas diferentes: o nome do projeto, uma **dependência npm** (`danfojs`), uma **URL real de deploy** e um **substantivo comum**. Só a primeira era escopo. O trabalho estava em classificar, não em substituir.
- **Rodar a baseline antes da primeira edição é o que separa "gate verde com ressalva" de "eu quebrei alguma coisa".** A falha do `osm.test.ts` já existia; sem a baseline de 11:23 a suíte final pareceria regressão e teria custado uma investigação inteira.
- **Teste que depende de backoff real vira bomba-relógio.** A BG-008 introduziu retry com espera de relógio de parede e um teste escrito antes dela passou a estourar timeout — sem ninguém mexer no teste. Onde há espera, injete o `sleep` (o `fetchRoadGraph` já expõe o override; o teste é que não usou).
- **Renomear chave de persistência é mudança de produto, não de cosmética.** `DB_NAME` parece uma string qualquer no meio de um arquivo de serviço, mas trocá-la apaga os dados de todo usuário existente. Merece a mesma cerimônia de confirmação que um `DROP TABLE`.
