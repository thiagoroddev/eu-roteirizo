## Planejamento Aprovado

### Investigação (evidência)
- `danfojs` usado só em 2 experimentos não-wired: `__utilidades-back-office__/DanfoTest.tsx:6` e `DanfoTest1.tsx:16` (`dfd.readExcel`). Nenhum script npm os invoca.
- Produção (`src/`) lê planilha via `xlsx` direto (0.20.3) em `src/utils/excelProcessor.ts`; scripts `analise-risco`/`extrair-complementos` usam `xlsx` direto (`extrairComplementos.ts:41`), não danfojs.
- Conclusão: o `xlsx@0.19.3` vulnerável (GHSA-5pgg-2g8v-p4x9) só era exercitado nos experimentos; não entrava no bundle de produção. Risco real em produção ≈ nulo. Objetivo: zerar o `npm audit` e proteger os experimentos.

### Abordagem aprovada: npm `overrides`
- Adicionar `"overrides": { "danfojs": { "xlsx": "$xlsx" } }` ao `package.json` — força a cópia aninhada do xlsx (dentro do danfojs) a usar a mesma versão da dependência raiz (0.20.3 da CDN, corrigida).
- Reinstalar, verificar audit + `npm ls xlsx`, rodar gates.

## Decisões Tomadas
- **`overrides` com `"$xlsx"` em vez de fixar versão literal:** referencia a versão da dependência raiz (CDN 0.20.3), evitando duplicar a string da CDN e mantendo o danfojs em sincronia automática com o xlsx do projeto.
- **Não remover o danfojs nesta tarefa:** abordagem cirúrgica que não deleta os experimentos. A remoção (mais limpa a longo prazo) fica como possibilidade futura, não obrigatória.

## O Que NÃO Foi Feito (e Por Quê)
