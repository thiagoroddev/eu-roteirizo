## Decisões Tomadas
- **Lazy deletion em vez de decrease-key:** o heap binário simples não tem decrease-key; reempurrar o nó com a nova prioridade e pular duplicatas liquidadas (`settled`) é o padrão correto para A*. Como a heurística haversine é **consistente** (desigualdade triangular), cada nó é liquidado **uma vez no g ótimo** → caminho/distância **idênticos** à versão linear.
- **Classe (não factory):** um heap é naturalmente stateful; classe é mais legível. `erasableSyntaxOnly` permite classes (proíbe só enum/namespace/parameter-property) — evitei o `constructor(private compare)` e declarei o campo explicitamente.
- **Equivalência via regressão, não comparação A/B:** a versão linear foi substituída; os 7 testes existentes do `aStar` (paths únicos) são a prova de "resultado idêntico" e passaram sem mudança. O teste de escala valida correção (caminho ótimo monotônico) num grafo grande.
- **Sem assert de tempo no CI (flaky):** o teste de escala loga o tempo em DEV e confia no timeout do vitest (5 s) como backstop contra travamento. O número real foi medido e registrado abaixo.
